# traffic-lab

> 부하를 걸어 **p99이 무너지는 순간을 재현하고**, 그 신호를 AI 트리아지로 연결하는 실험장.

백엔드 개발자로서 트래픽 대응 경험을 쌓기 위한 학습 프로젝트입니다.
"서버가 느리다"가 아니라 **"무엇이 병목인지 데이터로 말할 수 있는 상태"**를 목표로 합니다.

---

## 핵심 결과 한 장

풀 크기 5, 쿼리 비용 `10ms(95%) / 400ms(5%)`, 이론상 한계 **169 RPS**인 서버에 부하를 계단식으로 올린 결과:

| VU | RPS | p50 | p99 | **p99 / p50** | 에러율 |
|---:|---:|---:|---:|---:|---:|
| 2 | 71 | 11.18ms | 442.76ms | **40배** | 0% |
| 5 | 169 | 10.89ms | 461.22ms | **42배** | 0% |
| 10 | 167 | 34.90ms | 492.09ms | 14배 | 0% |
| 20 | 164 | 83.95ms | 559.86ms | 6.7배 | 0% |
| 40 | 164 | 194.14ms | 724.22ms | 3.7배 | 0% |
| 80 | 157 | 450.15ms | 1.03s | 2.3배 | 0% |
| 150 | 184 | 750.45ms | 1.25s | 1.7배 | 0% |
| 500 | 181 | 2.76s | 3.29s | 1.2배 | **7.29%** |

여기서 얻은 것 세 가지:

1. **5 VU 구간에서 p50은 10.9ms로 완벽해 보이지만 p99는 461ms — 42배입니다.**
   평균이나 중앙값만 보고 있었다면 이 장애를 통째로 놓쳤습니다.
2. **RPS는 5 VU 이후 165 언저리에서 고정됩니다.** 부하를 30배 더 줘도
   처리량은 그대로고 지연만 늘어납니다. 이론 계산값(169 RPS)과 2% 이내로 일치했습니다.
3. **p99/p50 격차는 포화가 깊어질수록 오히려 줄어듭니다** (42배 → 1.2배).
   격차가 벌어지는 건 붕괴 신호가 아니라 **초기 경고**입니다.

그리고 풀 크기를 10배로 키워 재측정했더니 p99이 **864ms → 482ms로 절반만** 줄었다.
남은 482ms는 큐가 아니라 비싼 쿼리 자체의 비용이다.

> 풀 크기는 **큐 대기**를 줄인다. **이질성**은 못 없앤다.

자세한 측정 과정과 해석은 [`docs/03-experiments.md`](docs/03-experiments.md).

## 빠른 시작

```bash
go mod tidy          # 최초 1회
docker compose up -d # Prometheus + Grafana
go run .             # 서버 (별도 터미널)
k6 run k6/load.js    # 부하 (또 다른 터미널)
```

- Grafana → http://localhost:3000 → 대시보드 **traffic-lab — RED + 병목**
- Prometheus → http://localhost:9090 (알럿은 `/alerts`)

## 엔드포인트

| 경로 | 설명 |
|---|---|
| `GET /api/users` | **병목.** 커넥션 풀을 거쳐야 하고 쿼리 비용이 요청마다 다름 |
| `GET /api/health` | 풀을 안 씀. 부하 중에도 빨라야 하는 **대조군** |
| `GET /metrics` | Prometheus 스크레이프 대상 |

## 설정

| 변수 | 기본값 | 의미 |
|---|---|---|
| `POOL_SIZE` | 5 | 커넥션 풀 크기 ← **가장 재미있는 손잡이** |
| `QUERY_MS` | 10 | 싼 쿼리 소요 시간 |
| `SLOW_QUERY_MS` | 400 | 비싼 쿼리 소요 시간 |
| `SLOW_PCT` | 5 | 비싼 쿼리의 비율(%) |
| `ACQUIRE_TIMEOUT_MS` | 3000 | 이만큼 기다려도 커넥션을 못 얻으면 503 |
| `PORT` | 8080 | |

> **이론상 한계 처리량 = 풀 크기 ÷ 평균 쿼리 시간**
> 기본값이면 `5 ÷ 0.0295s ≈ 169 RPS`. 서버가 시작할 때 이 값을 직접 출력합니다.

## 기술 스택

Go 1.27 · Prometheus · Grafana · k6 · Docker Compose

## 검증 상태

전 구간을 실제로 연결해 확인했다. 문서의 모든 수치는 실측값이다.

| | |
|---|---|
| 구성 | Docker 29.8.0 / Compose v5.5.1 / Prometheus v3.14.0 / Grafana 13.2.1 |
| 스크레이프 | `host.docker.internal:8080` health=up |
| 대시보드 | 패널 7개 자동 등록, Grafana 13에서 정상 |
| 부하 | 53,692 요청 / 3분 / 에러 0건 |
| 알럿 | `DBPoolSaturated` 발화 — **원인 알럿이 결과 알럿보다 먼저** |

부하 중 p99 지연의 **98.2%가 순수 커넥션 대기**였다.
이 수치가 "서버가 느리다"와 "풀이 병목이다"를 가른다.
