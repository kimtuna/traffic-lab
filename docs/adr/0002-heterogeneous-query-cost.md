# ADR-0002. 쿼리 비용을 이질적으로 모델링한다

**상태:** 채택 · 2026-09-15
**대체하는 결정:** 초기 구현의 균등 비용 모델(모든 쿼리 50ms)

## 맥락

초기 구현은 모든 요청의 쿼리 비용을 **50ms 균등**(±30% 지터)으로 잡았다.
풀 크기를 5로 제한했으니 부하가 올라가면 큐가 생기고,
**p50은 정상인데 p99만 먼저 치솟을 것**으로 예상했다.

측정해보니 그렇지 않았다.

| VU | p50 | p99 | p99/p50 |
|---:|---:|---:|---:|
| 3 | 51.23ms | 65.76ms | 1.28배 |
| 10 | 101.85ms | 126.28ms | 1.24배 |
| 25 | 255.06ms | 284.16ms | 1.11배 |
| 100 | 1.01s | 1.05s | **1.04배** |

**어느 구간에서도 p50과 p99이 갈라지지 않았다.** 최대 격차가 1.47배였고,
부하가 올라갈수록 오히려 붙었다.

### 원인

모든 요청의 서비스 시간이 동일했기 때문이다. 이 조건에서 FIFO 큐는
모든 요청을 공평하게 대우하므로 **"운 나쁜 1%"가 생길 원인이 없다.**

closed-loop 부하에서는 Little's Law가 지배한다:

```
지연 = VU 수 ÷ 처리량 = 100 ÷ 98.6 = 1.01s
```

측정된 p50과 정확히 일치한다. 모두가 똑같이 1초씩 기다린 것이지,
일부가 불운했던 게 아니다. **부하는 분포의 모양이 아니라 위치만 옮겼다.**

현실에서 p99이 튀는 이유는 부하 그 자체가 아니라,
부하가 걸렸을 때 **드러나는 이질성**이다 — 무거운 쿼리, GC 일시정지,
캐시 미스, 락 경합. 모델에 이질성이 없으면 p99도 없다.

## 결정

**요청마다 쿼리 비용을 다르게 만든다.**

```go
type costModel struct {
    fast    time.Duration // 10ms — 대부분의 요청
    slow    time.Duration // 400ms — 무거운 소수
    slowPct float64       // 5%
}
```

현실의 근거가 있는 설정이다. 대부분의 사용자는 레코드 몇 개만 읽지만,
어떤 사용자는 수만 건을 조회한다. 그 비싼 소수가 5개뿐인 커넥션을
오래 점유하면 뒤에 줄 선 싼 요청까지 막힌다 — **head-of-line blocking**.

## 고려한 대안

### 대안 A — 균등 모델 유지하고 문서를 고친다
관측된 현상(처리량 천장, Little's Law, 503)만 설명하고
p99 이야기는 빼는 방법.

**기각 이유:** 처리량 천장은 이미 균등 모델에서도 잘 보였지만,
**p99을 보는 이유 자체**가 이 프로젝트의 출발점이다.
그걸 재현 못 하는 실험장은 목적을 놓친다.

### 대안 B — GC 일시정지나 락 경합을 흉내 낸다
`runtime.GC()`를 주기적으로 호출하거나 전역 뮤텍스를 거는 방법.

**기각 이유:** 이질성을 만들긴 하지만 **원인이 불명확하다.**
쿼리 비용 차이는 백엔드 개발자에게 즉시 이해되고,
`SLOW_PCT` 하나로 강도를 조절할 수 있다.

### 대안 C — 로그정규분포 같은 연속 분포
현실의 응답 시간 분포에 더 가깝다.

**기각 이유:** 이질성의 **원인이 파라미터로 안 드러난다.**
`5%가 40배 비싸다`는 설명은 한 줄로 끝나지만,
`σ=1.2인 로그정규분포`는 그렇지 않다. 학습용으로는 명료함이 낫다.
나중에 필요하면 `costModel`만 갈아끼우면 된다.

## 결과

재측정 결과 가설이 성립했다.

| VU | RPS | p50 | p99 | p99/p50 |
|---:|---:|---:|---:|---:|
| 5 | 169 | 10.89ms | 461.22ms | **42.4배** |
| 20 | 164 | 83.95ms | 559.86ms | 6.7배 |
| 80 | 157 | 450.15ms | 1.03s | 2.3배 |
| 500 | 181 | 2.76s | 3.29s | 1.2배 |

**얻은 것**
- p50 10.9ms / p99 461ms — **평균이 장애를 숨기는 장면**을 재현했다
- 예상 못 한 발견: **p99/p50 격차는 포화가 깊어질수록 줄어든다**(42배 → 1.2배).
  큐 대기가 모두에게 공통으로 더해지며 원래 비용 차이를 희석시키기 때문이다.
  실전 함의가 크다 — **격차가 벌어지는 건 붕괴가 아니라 초기 경고**다
- 이론 한계 처리량이 `풀 크기 ÷ 평균 서비스 시간`으로 여전히 계산 가능하다
  (169 RPS 예측, 측정 오차 2% 이내)

**잃은 것**
- 파라미터가 3개(`QUERY_MS`, `SLOW_QUERY_MS`, `SLOW_PCT`)로 늘어 실험 공간이 넓어졌다
- 실행마다 난수가 개입해 측정값 재현성이 약간 떨어진다.
  측정 구간을 12초 이상으로 잡아 완화했다

## 이 결정에서 배운 것

> **모델이 재현 못 하는 현상은 설명할 수도 없다.**

가설이 틀렸다는 걸 측정으로 확인한 게 이 프로젝트에서 가장 값진 순간이었다.
측정하지 않았다면 "p99은 부하 때문에 튄다"는 **부정확한 이해**를
그대로 가져갔을 것이다. 실제 원인은 부하가 아니라 **부하가 드러낸 이질성**이다.

## 재검토 조건

- 실제 DB로 교체하면 이질성이 자연 발생하므로 이 모델은 제거한다
- GC나 락 경합 같은 **다른 종류의 이질성**을 관측하고 싶어지면 확장한다
